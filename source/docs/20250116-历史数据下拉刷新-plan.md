# 历史数据下拉刷新功能开发计划

## 需求背景

用户需要在历史数据页面实现下拉刷新功能，当用户下拉时，从单片机重新请求最新的历史数据进行同步。这样可以方便用户手动刷新历史数据，获取最新的记录。

## 实现方案

### 1. 技术选型

- 使用 Jetpack Compose Material3 的 `PullRefresh` 组件
- 当前项目使用的 Compose BOM 版本为 `2024.09.00`，完全支持 `PullRefresh` 组件
- 利用现有的 `isFetchingHistory` 状态来控制刷新指示器

### 2. 实现逻辑

1. **下拉刷新UI**：
   - 在 `HistoryScreen` 的 `LazyColumn` 外层包裹 `PullRefresh` 组件
   - 使用 `isFetchingHistory` 作为刷新状态指示
   - 只有在已连接状态下才允许下拉刷新

2. **数据刷新流程**：
   - 用户下拉时触发 `onRefresh` 回调
   - 调用 `viewModel.fetchHistory()` 从单片机请求历史数据
   - `fetchHistory()` 内部会通过蓝牙通知接收数据，保存到数据库
   - 监听 `isFetchingHistory` 状态变化，当从 `true` 变为 `false` 时（数据获取完成）
   - 调用 `viewModel.loadHistoryDetail()` 重新从数据库加载最新数据并刷新列表

3. **状态管理**：
   - 使用现有的 `isFetchingHistory` StateFlow 来控制刷新指示器
   - 使用现有的 `connectionState` 来判断是否可以刷新

### 3. 文件修改

需要修改的文件：
- `app/src/main/java/com/example/pandatemperature/ui/screen/HistoryScreen.kt`
  - 导入 `PullRefresh` 相关组件
  - 在 `LazyColumn` 外层包裹 `PullRefresh`
  - 添加刷新完成后的数据重新加载逻辑

## 注意事项

- 确保在刷新过程中不会重复触发请求（`fetchHistory()` 内部已有检查）
- 刷新完成后的数据重新加载需要使用 `LaunchedEffect` 监听状态变化
- 需要正确处理未连接状态下的刷新禁用
