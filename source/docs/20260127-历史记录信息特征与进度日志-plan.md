# 历史记录信息特征与进度日志开发计划

## 需求背景

- 单片机端已经新增 **历史记录信息特征**（UUID 与原电池电量特征相同），用于一次性返回：
  - 总记录数 `totalRecords`（uint32，小端）
  - 起始扇区 `startSector`（uint16，小端）
  - 起始记录索引 `startIndex`（uint16，小端）
- Android 端目前：
  - 还未使用该特征，获取历史数据时不知道总记录数；
  - 日志中只能看到“开始获取历史数据”“解析完成”等粗粒度信息，缺少进度反馈；
  - 电池电量特征已在协议层暂时被复用，因此需要在 App 侧“屏蔽电池功能”，避免误用。

目标：

1. 在 Android 端支持 **历史记录信息特征** 的读取；
2. 在获取历史数据时，能够：
   - 先读取总记录数及起始位置；
   - 在日志中实时显示类似 `正在加载历史数据[1/600](1/6)` 的进度信息；
3. 暂时 **禁用电池电量读取/订阅**，避免与新的历史信息特征冲突。

## 实现方案

### 1. 协议常量与 GATT 层改造

1.1 `BleConstants.kt`

- 新增常量：
  - `HISTORY_INFO_CHAR`：使用与单片机端一致的 UUID（当前与电池电量特征相同）。
- 保留 `BATTERY_CHAR` 常量，但在注释中标明：
  - 该 UUID **当前在固件中作为历史信息特征使用**；
  - 电池电量功能暂时关闭。

1.2 `BleManager.kt`

- 新增字段：
  - `historyInfoCharacteristic: BluetoothGattCharacteristic?`
- 在 `cacheServices()` 中：
  - 从 `CONFIG_SERVICE` 中获取 `HISTORY_INFO_CHAR` 对应特征并缓存；
- 在 `getCharacteristicByUuid()` 中：
  - 为 `BleConstants.HISTORY_INFO_CHAR` 返回 `historyInfoCharacteristic`；
- 电池相关字段/缓存保留，但 **不再在业务逻辑中使用**。

### 2. 业务逻辑层：读取历史信息 + 进度日志

2.1 `MainViewModel.kt` 新增状态变量

- 历史信息相关：
  - `expectedHistoryTotal: Long?` —— 期望总记录数（从历史信息特征读取到的值）；
  - `historyStartSector: Int?` / `historyStartIndex: Int?` —— 起始位置（仅用于日志，便于排查问题）。
- 进度统计相关：
  - `totalHistoryReceivedCount: Int` —— 本次会话累计已接收记录数（与数据库保存解耦）；
  - `historyPacketIndex: Int` —— 已接收数据包序号（从 1 开始）；
  - `historyPacketTotalEstimate: Int?` —— 估算总包数（根据第一包记录数和总记录数估算）；
  - `historyRecordsPerPacketEstimate: Int?` —— 估算每包记录数（第一包解析得到）。

2.2 获取历史信息的读取流程

- 在 `fetchHistory(lastTimestamp: Long = 0)` 内，正式写入时间戳之前：
  1. 检查是否支持 `HISTORY_INFO_CHAR`（通过 `bleManager.isCharacteristicAvailable`）；
  2. 支持时调用 `bleManager.readCharacteristic(BleConstants.HISTORY_INFO_CHAR)`：
     - 期望获得 8 字节：
       - [0-3] `totalRecords` (uint32，小端)
       - [4-5] `startSector` (uint16，小端)
       - [6-7] `startIndex` (uint16，小端)
     - 解析后写入 `expectedHistoryTotal` 等变量；
     - 使用 `addLog` 输出一条日志，例如：
       - `"历史记录信息：总记录数 600，起始扇区 10，起始索引 0"`；
  3. 若读取失败或特征不可用：
     - 打一条提示日志，继续执行原有历史获取逻辑（无进度条，保持向后兼容）。

2.3 历史数据解析与进度日志

- 在 `processHistoryData(data: ByteArray)` 中：
  - 保持原有 **10 字节（带气压）/8 字节旧格式** 解析逻辑；
  - 对于每条成功解析的记录：
    - `totalHistoryReceivedCount++`；
  - 对于每个数据包：
    - `historyPacketIndex++`；
    - 统计本包 `recordsInPacket`；
    - 若是第一包：
      - 记录 `historyRecordsPerPacketEstimate = recordsInPacket`；
      - 若 `expectedHistoryTotal` 有值：
        - 估算 `historyPacketTotalEstimate = ceil(expectedHistoryTotal / recordsInPacket)`；
  - 在合适时机输出进度日志（避免刷屏）：
    - 触发时机：
      - 每收到一整包数据后；
      - 或每累计 N 条记录（例如 20 条）后；
    - 日志格式（在 `expectedHistoryTotal` 存在时）：
      - `正在加载历史数据[当前/总数](当前包/估算总包数)`  
      - 示例：`正在加载历史数据[120/600](3/6)`；
    - 若没有总数信息（旧固件或者读取失败）：
      - 仅打印已接收数量，例如：`正在加载历史数据[当前/未知]`。

2.4 获取完成与状态重置

- 在 `finishHistoryFetch()` 中：
  - 调用 `saveHistoryToDatabase()` 后：
    - 重置：
      - `expectedHistoryTotal = null`
      - `historyStartSector = null`
      - `historyStartIndex = null`
      - `totalHistoryReceivedCount = 0`
      - `historyPacketIndex = 0`
      - `historyPacketTotalEstimate = null`
      - `historyRecordsPerPacketEstimate = null`
  - 保持原有：
    - 关闭通知；
    - 更新 `_isFetchingHistory`；
    - 清空任务状态等逻辑。

### 3. 电池电量功能暂时屏蔽策略

- 在 `MainViewModel.kt` 中：
  - 保留 `readBatteryVoltage()` 与 `subscribeBatteryVoltage()` 方法签名，但在方法内部：
    - 直接通过 `addLog` 提示：
      - `"电池电量功能暂未启用（UUID 已被历史信息特征复用）"`；
    - 立即返回，不再调用 `bleManager.readCharacteristic` 和通知订阅；
- 在 `initializeDevice()` 等初始化流程中保持当前状态：**不再自动调用电池相关方法**。
