# 界面进一步优化和交互改进开发计划

## 需求背景

用户反馈：

1. 第一屏的温度湿度块还是太大了，需要进一步缩小
2. 更新时间应该做成文本放到"实时数据"标题的最右边
3. 读取温湿度按钮改成点击温湿度LABEL触发更新数据事件
4. 历史数据区域只获取最新的20条
5. 增加"点击更多"功能，支持分页展示温湿度数据
6. 蓝牙连接成功后，在订阅数据更新之前如果没有任何数据，应该自动触发一次获取数据

## 实现方案

### 一、温湿度块尺寸进一步优化

1. **温湿度数值区域缩小**
   - 减小padding：从16dp减少到10-12dp
   - 减小字体：从`headlineLarge`改为`headlineMedium`或`titleLarge`
   - 减小单位字体：从`titleMedium`改为`bodyLarge`
   - 减小标签字体：从`bodySmall`改为`bodySmall`（保持或更小）

### 二、更新时间显示位置调整

1. **标题行布局重构**
   - "实时数据"标题和更新时间放在同一行
   - 标题在左侧，更新时间在右侧
   - 使用Row布局，Spacer填充中间空间
   - 移除独立的更新时间Surface区域

### 三、读取按钮改为Label点击触发

1. **移除按钮**
   - 移除"读取温度"和"读取湿度"按钮
   - 移除按钮组Row布局

2. **Label添加点击功能**
   - 为温度Label（显示"温度"文字的Text）添加`clickable`修饰符
   - 为湿度Label（显示"湿度"文字的Text）添加`clickable`修饰符
   - 添加点击反馈（可选：添加视觉反馈如alpha变化）

3. **参数调整**
   - 将`onReadTemperature`和`onReadHumidity`保留
   - 在Label点击时调用对应的回调函数

### 四、历史数据限制和分页功能

1. **DAO层增加分页查询**
   - 添加`getLatestRecords(limit: Int)`方法，查询最新的N条记录
   - 添加`getRecordsWithOffset(limit: Int, offset: Int)`方法，支持分页查询

2. **ViewModel层支持分页**
   - 添加`_displayedHistoryRecords`状态，存储当前显示的记录
   - 添加`_historyPageSize`状态，默认20条
   - 添加`_hasMoreHistory`状态，判断是否还有更多数据
   - 修改历史数据查询逻辑，首页默认只加载20条
   - 添加`loadMoreHistory()`方法，加载下一页数据

3. **创建新的历史数据页面**
   - 创建`HistoryScreen.kt`作为历史数据详情页面
   - 实现分页显示逻辑
   - 支持滚动加载更多（或分页按钮）

4. **UI层调整**
   - HistoryCard默认只显示最新的20条
   - 添加"点击更多"按钮/文本
   - 点击后弹出新的历史数据页面（全屏或对话框）
   - 新页面中显示所有历史数据，支持分页加载

### 五、蓝牙连接后自动获取数据

1. **订阅前数据检查**
   - 在`subscribeRealtimeData()`调用前，检查`temperature`和`humidity`是否为null
   - 如果都为null，自动调用`readTemperature()`和`readHumidity()`
   - 等待读取完成后再进行订阅

2. **优化初始化流程**
   - 在`initializeDevice()`中，先读取一次数据，再订阅
   - 确保用户能看到初始数据

## 注意事项

1. **点击体验**：Label点击时要提供良好的视觉反馈
2. **分页性能**：注意分页查询的性能，避免一次性加载过多数据
3. **数据一致性**：确保分页加载的数据顺序正确（最新的在前）
4. **自动获取**：确保自动获取数据不会干扰订阅功能
5. **用户体验**：分页加载时要提供加载状态提示
