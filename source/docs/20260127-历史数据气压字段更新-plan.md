# 历史数据气压字段更新 - 开发计划

## 需求背景

根据最新的蓝牙协议v1.1文档，历史数据记录格式更新：
- **最后2字节字段变更**：从 `voltage_mV(uint16)` 改为 `pressure_dhpa(uint16)`
- **单位说明**：`pressure_dhpa` 单位是 0.1 hPa（即需要除以10得到标准hPa）
- **记录格式**（10字节，小端序）：
  - `timestamp`: uint32（Unix时间戳，秒）
  - `temp_raw`: int16（温度，0.01°C）
  - `hum_raw`: uint16（湿度，0.01%RH）
  - `pressure_dhpa`: uint16（气压，0.1 hPa）

> 注意：电池电压仍然通过独立的 `BATTERY_CHAR` 特征获取，不受此变更影响。

## 实现方案

### 1. 更新数据模型（TemperatureRecord.kt）

**变更内容**：
- 将 `voltage: Float?` 字段改为 `pressure: Float?` 字段（单位：hPa）
- 更新注释说明

**影响范围**：
- 数据库需要升级（版本2 -> 3）
- 历史数据解析逻辑需要更新

### 2. 更新数据库（AppDatabase.kt）

**变更内容**：
- 数据库版本从2升级到3
- 由于使用了 `fallbackToDestructiveMigration()`，旧数据会被清空（开发阶段可接受）

**影响范围**：
- 用户本地历史数据会被清空（开发阶段可接受）

### 3. 更新ViewModel（MainViewModel.kt）

**变更内容**：
- 更新历史数据解析逻辑：
  - 将最后2字节从 `voltage_mV` 改为 `pressure_dhpa`
  - 单位转换：`pressure_dhpa / 10.0f` 得到标准hPa
  - 更新相关注释

**影响范围**：
- 历史数据解析逻辑变更
- 不影响电池电压功能（通过独立特征获取）

## 技术细节

### 1. 数据格式转换

**新格式（10字节）**：
- Timestamp: 4 bytes (uint32_t)
- Temperature: 2 bytes (int16_t, 0.01°C)
- Humidity: 2 bytes (uint16_t, 0.01%)
- Pressure: 2 bytes (uint16_t, 0.1 hPa) ⭐ 更新：从voltage改为pressure

**单位转换**：
- `pressure_dhpa` 读取后需要除以10得到标准hPa
- 例：`pressure_dhpa = 10135` 表示 `1013.5 hPa`

**旧格式（8字节）兼容**：
- Timestamp: 4 bytes
- Temperature: 2 bytes
- Humidity: 2 bytes
- 无气压字段（pressure = null）

### 2. 数据库迁移

由于使用 `fallbackToDestructiveMigration()`，数据库升级时会清空旧数据。这是开发阶段的可接受行为。

如果未来需要保留数据，需要：
1. 实现 `Migration` 类（从版本2到版本3）
2. 在 `AppDatabase` 中配置迁移策略
3. 将 `fallbackToDestructiveMigration()` 改为 `.addMigrations(...)`

### 3. 字段命名说明

- **历史数据中的气压**：`pressure`（Float，单位hPa，可选）
- **电池电压**：通过 `BATTERY_CHAR` 特征独立获取，存储在 `_batteryVoltage` StateFlow中，不受此变更影响

## 注意事项

1. **向后兼容**：
   - 历史数据解析需要兼容旧格式（8字节，无气压字段）
   - 旧数据中 `pressure` 字段为 `null`

2. **数据丢失**：
   - 数据库升级会清空旧数据（开发阶段可接受）
   - 如果生产环境需要保留数据，需要实现迁移策略

3. **测试重点**：
   - 新格式历史数据解析（10字节，包含气压）
   - 旧格式历史数据兼容性（8字节，无气压）
   - 电池电压功能不受影响（独立特征）

4. **性能考虑**：
   - 数据解析逻辑变更很小，性能影响可忽略

## 总结

本次更新主要是协议适配，将历史数据中的最后2字节从电压改为气压：
1. 数据模型字段更新（voltage -> pressure）
2. 历史数据解析逻辑更新（voltage_mV -> pressure_dhpa，单位转换）
3. 数据库版本升级（2 -> 3）

实现时需要注意向后兼容，确保旧格式（8字节）数据仍能正常解析。
