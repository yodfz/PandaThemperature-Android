# 蓝牙连接常驻通知 - 开发计划

## 需求背景

- 应用与蓝牙设备连接后，若手机熄屏或切到后台，系统可能因 Doze/应用待机/内存回收而结束进程，导致蓝牙断开。
- 通过「连接期间运行前台服务并显示常驻通知」，可降低被系统杀进程的概率，保持熄屏/后台时连接稳定。
- 用户手动从最近任务划掉应用仍会断连（系统设计，无法避免）。

## 实现方案

1. **新增前台 Service**

   - 包路径：`service/BleConnectionForegroundService.kt`（与 data/ui 平级，保持架构清晰）。
   - 职责：在 `onStartCommand` 中立即调用 `startForeground`，展示一条不可划掉的常驻通知；不持有 BLE 逻辑，仅保活进程。
   - 通知：单独通知渠道（如「蓝牙连接」），标题/内容使用 strings 资源；点击通知进入 MainActivity。

2. **启停时机**

   - **启动**：在 MainViewModel 的 `connectionState` 收集逻辑中，当状态变为 `ServicesDiscovered`（连接就绪）时，带设备名等信息的 Intent 启动 Service。
   - **停止**：当状态变为 `Disconnected` 时调用 `stopService`；用户点击断开也会触发 `Disconnected`，无需在 `disconnectDevice()` 里重复停服务。

3. **Manifest 与权限**

   - 声明 `BleConnectionForegroundService`，并设置 `android:foregroundServiceType="connectedDevice"`（Android 10+）。
   - 已有 `FOREGROUND_SERVICE`；为 Android 14+ 增加 `FOREGROUND_SERVICE_CONNECTED_DEVICE` 权限声明。

4. **字符串与渠道**
   - 在 `strings.xml` 中增加通知渠道名称、描述及通知标题、内容文案。

## 注意事项

- 不在 Service 内持有 Activity 或 View 引用，仅用 ApplicationContext。
- 通知点击使用 `PendingIntent.getActivity` 打开 MainActivity，设置合适 flag 避免多实例。
