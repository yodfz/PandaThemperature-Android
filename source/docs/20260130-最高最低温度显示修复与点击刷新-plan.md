# 最高最低温度显示修复与点击刷新功能

## 需求背景

用户反馈最高温湿度无法显示，经排查发现是 `MaxMinTempParser` 解析器的判断逻辑问题。同时用户希望增加点击最高最低温度标签重新获取数据的功能。

## 问题分析

### 问题1：判断逻辑错误

在 `MaxMinTempParser.parseNewFormat()` 中：

```kotlin
val hasMaxRecord = maxTempRaw != MAX_TEMP_RESET_VALUE && maxTimestamp != 0L
val hasMinRecord = minTempRaw != MIN_TEMP_RESET_VALUE && minTimestamp != 0L
```

该逻辑要求**温度不是重置值 且 时间戳不为0** 才算有效记录。

但根据协议定义："最高温度 = -32768 **且** 时间戳 = 0 表示未记录/已重置"

**正确逻辑**：只有当温度是重置值 **且** 时间戳为0时才算未记录。如果温度有效但时间戳为0，应该仍然显示温度（只是不显示时间）。

### 问题2：缺少手动刷新功能

目前没有手动重新获取最高最低温度的 UI 入口。

## 实现方案

### 方案1：修复 MaxMinTempParser 判断逻辑

修改 `parseNewFormat()` 中的判断：

```kotlin
// 修改前（错误）：
val hasMaxRecord = maxTempRaw != MAX_TEMP_RESET_VALUE && maxTimestamp != 0L

// 修改后（正确）：
// 只有温度是重置值 且 时间戳为0 才表示未记录
val isMaxReset = maxTempRaw == MAX_TEMP_RESET_VALUE && maxTimestamp == 0L
val hasMaxRecord = !isMaxReset
```

### 方案2：添加点击刷新功能

在 `RealtimeDataCard` 组件中：
1. 给"最高/最低"文字区域添加 `clickable` 修饰符
2. 点击时调用回调函数 `onRefreshMaxMinTemp()`
3. 在 `MainScreen` 中传递 `viewModel.readMaxMinTemperature()` 作为回调
