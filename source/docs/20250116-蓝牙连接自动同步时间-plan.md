# 蓝牙连接自动同步时间开发计划

## 需求背景

用户需要在蓝牙设备连接成功后，自动将当前时间同步给设备，确保设备时间与手机时间一致。

## 现状分析

1. **已有实现**：
   - `MainViewModel.initializeDevice()` 方法中已调用 `syncTime()`
   - `syncTime()` 方法已实现时间同步功能
   - 连接状态变为 `ServicesDiscovered` 时会自动调用 `initializeDevice()`

2. **潜在问题**：
   - `syncTime()` 是异步方法，但 `initializeDevice()` 中调用后立即 delay，可能时间同步还未完成
   - 缺少错误重试机制
   - 时间同步失败时没有自动重试

## 实现方案

### 优化策略

1. **改进 `syncTime()` 方法**：
   - 将 `syncTime()` 改为 suspend 函数，确保可以等待完成
   - 增加写入完成的确认机制（通过写入回调）
   - 增加重试机制（最多重试2次）

2. **优化 `initializeDevice()` 方法**：
   - 确保时间同步完成后再继续后续操作
   - 增加适当的延迟，确保服务完全就绪
   - 添加更详细的日志记录

3. **错误处理**：
   - 时间同步失败时记录详细错误信息
   - 如果重试后仍失败，继续执行其他初始化操作（不阻塞）

- [x] 3. 优化 `initializeDevice()` 方法，确保时间同步完成后再继续

## 文件变更

### 修改的文件

1. **`data/bluetooth/BleManager.kt`**
   - 添加 `writeCallbacks` 映射，支持写入回调
   - 在 `onCharacteristicWrite` 回调中通知写入结果
   - 新增 `writeCharacteristic` 重载方法，支持异步回调
   - 在 `cleanup()` 中清理写入回调

2. **`ui/viewmodel/MainViewModel.kt`**
   - 将 `syncTime()` 改为私有 suspend 函数
   - 增加重试机制（最多重试2次）
   - 使用 `suspendCoroutine` 等待写入完成
   - 优化 `initializeDevice()` 中的调用方式，确保等待完成
   - 新增 `syncTimePublic()` 公开方法供外部调用
   - 增加详细的日志记录

3. **`ui/screen/SettingsScreen.kt`**
   - 更新调用方式，使用 `syncTimePublic()` 方法

## 注意事项

1. **异步处理**：确保时间同步操作是异步的，不阻塞 UI
2. **错误处理**：时间同步失败不应阻止其他初始化操作
3. **日志记录**：记录时间同步的详细过程，便于调试
4. **重试机制**：增加合理的重试次数和延迟，避免过度重试
