# 自动连接与电压展示开发计划

## 背景

当前 App 启动后需要用户进入设备选择流程，历史设备、首页、配置弹窗和历史记录也没有展示传感器上报的电池电压。本次先只改 Android App，不修改传感器固件：App 继续兼容现有 v1/v2 数据，并为未来固件扩展的实时 8 字节和历史 14 字节协议预留解析与存储能力。

## 实现方案

1. **启动自动连接**
   - 复用 MainActivity 已有的蓝牙权限申请和打开蓝牙流程。
   - 权限与蓝牙状态就绪后，仅在本次 App 启动流程中执行一次，查询 `devices` 表 `createTime` 最新的设备并按 MAC 地址连接。
   - 没有保存设备或自动连接失败时保留原手动选择设备入口；权限回调不再无条件弹出选择列表。
   - 用户主动断开后标记为手动断开，本次运行不再次自动连接。

2. **数据模型、协议与数据库**
   - `RealtimeData`、`ThermometerData`、`TemperatureRecord`、`Device` 增加可空 `batteryVoltage`/`latestBatteryVoltage`。
   - 实时协议保持 v1/v2 的 6 字节兼容；收到至少 8 字节时读取 offset 6 的小端毫伏并换算成伏特。
   - 通过现有 `DeviceProfile` 选择历史解析器：v1=8 字节、v2=12 字节、v3 及以上=14 字节，避免按数据长度模糊猜测。
   - Room 从 v9 升级到 v10，增加完整非破坏性 `MIGRATION_9_10`；补注册无数据变更的 `MIGRATION_8_9`，避免历史版本回退到 destructive fallback。
   - 实时数据更新设备最新电压；定时本机写入历史时保存当前电压。
   - 不启用与历史特征冲突的旧 `BATTERY_CHAR`，不计算 CR2032 电量百分比。

3. **页面展示**
   - 首页设备名/固件版本后显示一位小数电压，无数据不显示。
   - 设备配置弹窗打开时固定电压快照，显示在固件版本与存储记录之间；无数据显示 `--`。
   - 历史记录每行温度、湿度下方显示对应电压；旧记录显示 `-- V`。
   - 设备管理列表在固件版本下方、添加时间上方显示最新电压；无数据显示 `电池电压: --`。

4. **测试与交付**
   - 增加实时 6/8 字节、历史 8/12/14 字节解析单元测试。
   - 尽量执行 Gradle unit test 与 assembleDebug，记录无法构建时的准确原因。
   - 自查改动，排除 build/.gradle/local.properties 等机器产物后重新覆盖父仓库 `PandaThemperature-Android/src.zip`。

## 后续追加：电池电压「无效哨兵值」与量程合法性处理（固件 1.0.8）

### 背景

固件 1.0.8 把实时数据特征（`12340011-1234-5678-1234-56789abcdef0`）从固定 6 字节扩展为 8 字节：在原有「温度 i16 + 湿度 u16 + 气压 u16」之后，`offset 6` 起追加 2 字节小端 `uint16`，单位毫伏。无电压能力的固件仍上报 6 字节，App 必须继续兼容。

固件同时新增「无有效电压」哨兵值 `0xFFFF`（65535），用于 ADC 连续失败 / 尚未采到样。此前解析器没有任何有效性判断，会把 `0xFFFF` 换算成 `65535 / 1000 = 65.535 V`，界面上显示 `65.54V`——这属于必须修掉的显示事故。

只挡哨兵并不够：nRF52810 的工作电压是 **1.7 ~ 3.6 V**，本硬件上任何落在 `[1700, 3600]` mV 之外的读数都**物理上不可能**。因此本轮把「量程合法性」作为第二道防线一并落地，一次挡住三种情况：哨兵 `0xFFFF`、`0 mV`、以及 ADC 异常产生的畸形值。

### 改动点

1. `app/src/main/java/com/example/pandatemperature/data/device/parser/RealtimeDataParser.kt`（`RealtimeDataParserV2`）
   - 协议契约常量 `BATTERY_VOLTAGE_INVALID_MV = 0xFFFF`（固件显式哨兵）。
   - 量程常量 `BATTERY_VOLTAGE_MIN_MV = 1700`、`BATTERY_VOLTAGE_MAX_MV = 3600`；KDoc 注明依据 nRF52810 数据手册 1.7~3.6 V，并写明「哨兵是协议契约，量程检查是第二道防线，不是替代品」。
   - `parse()` 判定顺序：先 `== BATTERY_VOLTAGE_INVALID_MV` → 无效；再 `!in MIN..MAX` → 无效；否则 `mV / 1000f`。任一命中即 `batteryVoltage = null`。
   - 6 字节兼容逻辑不变：仅当 `data.size >= FRAME_SIZE_WITH_VOLTAGE`(8) 才解析电压；温度 / 湿度 / 气压解析未动。
2. `app/src/main/java/com/example/pandatemperature/data/device/model/RealtimeData.kt`
   - `ThermometerData` 新增 `batteryVoltageReported: Boolean`（默认 false），表示「本帧是否携带电压字段」，由解析器按帧长置位。
3. `app/src/main/java/com/example/pandatemperature/data/device/model/BatteryVoltageDisplay.kt`（新增，纯逻辑）
   - `resolveDisplayedBatteryVoltage(previous, frameVoltage, reported)` 是三态归约的**唯一判定来源**，无 Android 依赖，可在 JVM 单测中锁定。
4. `app/src/main/java/com/example/pandatemperature/ui/viewmodel/MainViewModel.kt`（`updateBatteryVoltage()`）
   - 原文开头的 `if (voltage == null) return` 早退（本地显示残留旧值的根源）已移除，改为调用三态归约；`reported = false` 时不写库（保留「旧 6 字节帧不覆盖」语义）。
5. `app/src/main/java/com/example/pandatemperature/data/bluetooth/BleFrameDiagnostics.kt`（`observeRealtime()`）
   - 日志区分三态：无效哨兵 / 超出量程 / 正常；`shouldReport` 去重逻辑未动，诊断仍不参与解析。
6. 单元测试：新增 `BatteryVoltageDisplayTest`（5 项，含三态回归）；扩充 `RealtimeDataParserTest`（12 项，覆盖量程边界）；`BleFrameDiagnosticsTest` 增 1 项（越界文案）。

### 电压有效性语义

| 帧 | `offset 6` 的 uint16 | 含义 | App 行为 |
|---|---|---|---|
| 6 字节 | 不存在 | 旧固件没有电压能力 | `batteryVoltageReported = false`；**保持既有显示**，不覆盖、不写库 |
| 8 字节 | `0xFFFF` | 固件哨兵（ADC 失败 / 未采到样） | 无效 → `batteryVoltage = null`，界面 `--`，并把设备记录写为 null |
| 8 字节 | `< 1700` 或 `> 3600`（含 `0x0000`） | 超出 nRF52810 量程，物理不可能 | 无效 → `null`，界面 `--` |
| 8 字节 | `1700 ~ 3600` | 合法读数 | `batteryVoltage = mV / 1000` |

UI 未改：四处电压展示对 `null` 的既有处理就是 `--`。未按 CR2032 曲线推算电量百分比（用户已否决）。
