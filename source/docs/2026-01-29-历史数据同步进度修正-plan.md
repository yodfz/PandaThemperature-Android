# 历史数据同步进度计算修正计划

## 需求背景
用户反馈在历史数据同步过程中，进度显示不准确：
1. **全量同步问题**：此前修复了全量同步时进度溢出的问题（从 0 开始计数）。
2. **增量同步问题**：用户指出在增量同步时，设备返回的是全量总数（例如 200 条），而本地已有部分数据（例如 150 条），设备只发送剩余的新数据（50 条）。此时如果从 0 开始计数，进度会显示为 1/200, 2/200... 最终 50/200，这会让用户误以为数据缺失。
3. **期望表现**：
   - **全量同步**（timestamp = 0）：初始进度 0，接收 N 条，最终 N/N。
   - **增量同步**（timestamp > 0）：初始进度 = 本地已有记录数（dbCount），接收 M 条，最终 (dbCount + M)/Total。

## 解决方案
修改 `MainViewModel.kt` 中的 `fetchHistory` 方法，根据同步模式动态设置初始进度计数。

### 逻辑变更
1. **调整执行顺序**：将 `timestamp`（起始时间戳）的确定逻辑移到设置 `totalHistoryReceivedCount` 之前。
2. **条件初始化**：
   - 如果 `timestamp > 0`（增量同步）：`totalHistoryReceivedCount = dbCount`（本地已有记录数）。
   - 如果 `timestamp == 0`（全量同步）：`totalHistoryReceivedCount = 0`。

### 代码修改
**文件**：`app/src/main/java/com/example/pandatemperature/ui/viewmodel/MainViewModel.kt`

```kotlin
// 1. 先确定起始时间戳
val timestamp = if (lastTimestamp > 0) {
    lastTimestamp
} else {
    getLastHistoryTimestamp()
}

// 2. 再设置初始进度
// 如果是增量同步（timestamp > 0），初始进度为本地已有记录数
// 如果是全量同步（timestamp == 0），初始进度为 0
totalHistoryReceivedCount = if (timestamp > 0) dbCount else 0
```

## 验证场景
假设设备总记录 200 条。

### 场景 A：首次同步（全量）
- 本地：0 条
- timestamp：0
- totalHistoryReceivedCount = 0
- 接收：200 条
- 进度：1/200 -> ... -> 200/200
- 结果：正确

### 场景 B：增量同步
- 本地：150 条
- timestamp：对应第 150 条的时间戳
- totalHistoryReceivedCount = 150
- 设备返回 Total：200
- 实际发送：50 条（第 151-200 条）
- 进度：151/200 -> ... -> 200/200
- 结果：正确

### 场景 C：强制全量同步（本地已有数据但强制重拉）
- 本地：150 条
- timestamp：0（手动指定）
- totalHistoryReceivedCount = 0
- 设备返回 Total：200
- 实际发送：200 条
- 进度：1/200 -> ... -> 200/200
- 结果：正确（覆盖本地数据）
