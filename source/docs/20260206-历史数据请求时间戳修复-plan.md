# 历史数据请求时间戳修复 - 开发计划

## 需求背景

用户反馈：请求历史数据时，会漏同步「手机记录时间戳以内」的设备数据。

### 问题分析

- **设备记录**：从设备同步下来的数据，无 GPS（latitude/longitude 为 null）
- **手机记录**：手机定时写入的数据，带 GPS

原先逻辑：只取「最新无 GPS 记录」的时间戳作为请求起点。当：

- 最新无 GPS 时间戳 = 10:00
- 最新有 GPS 时间戳 = 9:50（手机记录更早）

会发送 10:00，请求 `timestamp > 10:00`，导致设备在 9:50 ～ 10:00 之间的记录不会被拉取。

## 实现方案

在确定发送给设备的时间戳时，取 `min(最新无GPS时间戳, 最新有GPS时间戳)`，保证不会漏掉「手机记录时间戳以内」区间的设备数据。

### 开发计划

- [x] 1. 在 `TemperatureRecordDao` 中新增 `getLatestRecordWithGps(deviceId)` 方法
- [x] 2. 修改 `getLastHistoryTimestamp()`：同时查询无 GPS 与有 GPS 最新记录，取两者中更早的时间戳

### 逻辑说明

| 场景                   | 发送时间戳              |
| ---------------------- | ----------------------- |
| 无设备记录、无手机记录 | 0（全量）               |
| 仅有手机记录           | 0（全量）               |
| 仅有设备记录           | 设备最新时间戳          |
| 两者都有               | min(设备最新, 手机最新) |
