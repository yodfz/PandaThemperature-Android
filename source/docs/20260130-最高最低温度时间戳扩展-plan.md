# 最高最低温度时间戳扩展 - 开发计划

## 需求背景

蓝牙协议变更，最高最低温度特性（Temperature Range）数据格式已扩展：
- 数据长度从 4 字节扩展到 **12 字节**
- 新增最高/最低温度发生的时间戳字段

### 新数据格式（小端序，12字节）

| 字节偏移 | 长度 | 字段名称 | 数据类型 | 说明 |
|---------|------|----------|----------|------|
| 0-1 | 2 | max_temperature | int16 | 0.01°C |
| 2-5 | 4 | max_temperature_timestamp | uint32 | Unix时间戳（秒） |
| 6-7 | 2 | min_temperature | int16 | 0.01°C |
| 8-11 | 4 | min_temperature_timestamp | uint32 | Unix时间戳（秒） |

### 特殊值说明

| 场景 | max_temperature | max_timestamp | min_temperature | min_timestamp |
|-----|-----------------|---------------|-----------------|---------------|
| 未记录/已重置 | 0x8000 (-32768) | 0 | 0x7FFF (32767) | 0 |
| 正常记录 | 实际值 | 非0时间戳 | 实际值 | 非0时间戳 |

## 实现方案

### 1. 数据模型 `MaxMinTemperature` 扩展
- 添加 `maxTemperatureTimestamp: Long?` 字段
- 添加 `minTemperatureTimestamp: Long?` 字段
- 添加 `hasMaxRecord` 和 `hasMinRecord` 布尔属性

### 2. 解析器 `MaxMinTempParser` 更新
- 支持12字节新格式：解析时间戳
- 兼容4字节旧格式：时间戳为 null
- 处理特殊值判断

### 3. ViewModel 更新
- 添加 `_maxTemperatureTimestamp` 和 `_minTemperatureTimestamp` 状态
- 更新 `readMaxMinTemperature()` 方法

### 4. UI 层更新
- 修改 `calculateStats` 函数：优先使用设备时间戳

## 注意事项

1. 需要兼容4字节旧格式（老固件）
2. 时间戳依赖时间同步，时间戳为0表示未同步或未记录
3. 重置后 max=-32768, min=32767, 时间戳都为0
