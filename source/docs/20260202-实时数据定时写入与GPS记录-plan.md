# 实时数据定时写入与 GPS 记录功能

## 需求背景

用户需要在获取实时数据后，定时将数据写入数据库，并记录当前 GPS 坐标点。历史数据表需要增加 GPS 字段。

### 写入逻辑

1. 连接上设备后，等待获取 GPS 数据，获取到后立刻写入一次
2. 如果 30 秒内获取不到 GPS，放弃等待，立刻写入（GPS 为 null）
3. 之后每间隔 30 秒写入一次（带当前 GPS 坐标，如有）

### 其他需求

1. GPS 坐标如果有就显示在历史记录中
2. 后台继续写入，只要程序还在运行
3. 需要提示用户定位权限的用途

---

## 实现方案

### 1. 数据库层修改

#### 1.1 TemperatureRecord 实体增加 GPS 字段

- `latitude: Double?` - 纬度（可选）
- `longitude: Double?` - 经度（可选）

#### 1.2 数据库迁移（版本 6 → 7）

```sql
ALTER TABLE temperature_records ADD COLUMN latitude REAL DEFAULT NULL;
ALTER TABLE temperature_records ADD COLUMN longitude REAL DEFAULT NULL;
```

### 2. 定位模块

#### 2.1 权限声明（AndroidManifest.xml）

```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
```

#### 2.2 LocationManager 定位管理器

- 使用 FusedLocationProviderClient
- 提供获取当前位置的方法
- 支持超时处理

### 3. 定时写入逻辑（MainViewModel）

#### 3.1 状态管理

- `_currentLocation: MutableStateFlow<Location?>` - 当前位置
- `_isRecordingData: MutableStateFlow<Boolean>` - 是否正在记录数据

#### 3.2 写入流程

```
设备连接成功 (ServicesDiscovered)
    │
    ├── 启动定位请求
    │
    ├── 等待GPS（最多30秒）
    │   ├── 获取到GPS → 立刻写入第一条
    │   └── 30秒超时 → GPS为null，立刻写入第一条
    │
    └── 启动定时任务（每30秒）
        │
        └── 获取当前实时数据 + 当前GPS → 写入数据库

设备断开连接
    │
    └── 停止定时任务
```

### 4. UI 层更新

#### 4.1 权限请求

- 在 MainActivity 中添加定位权限请求
- 显示权限说明对话框

#### 4.2 历史记录显示 GPS

- 如果有 GPS 坐标，在历史记录项中显示
