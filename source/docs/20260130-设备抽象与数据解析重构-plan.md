# 设备抽象与数据解析重构 - 开发计划

## 需求背景

1. **数据解析逻辑分散**：温度、湿度、气压等解析逻辑在多处重复出现
2. **固件版本兼容**：需要支持老固件（无固件号，ESS服务）和新固件（有固件号，实时数据服务）
3. **设备类型扩展**：当前只有温度计，未来会有更多设备类型

## 实现方案

### 架构设计

```
data/
├── model/
│   ├── Device.kt                    // 设备实体（已有）
│   ├── DeviceStatus.kt              // 设备状态（已有）
│   └── TemperatureRecord.kt         // 温湿度记录（已有）
│
├── device/
│   ├── profile/
│   │   ├── DeviceProfile.kt         // 设备配置接口
│   │   ├── DeviceProfileFactory.kt  // 设备配置工厂
│   │   └── thermometer/
│   │       ├── ThermometerV1Profile.kt  // 老固件配置
│   │       └── ThermometerV2Profile.kt  // 新固件配置
│   │
│   ├── parser/
│   │   ├── DataParser.kt            // 解析器接口
│   │   ├── RealtimeDataParser.kt    // 实时数据解析器
│   │   ├── DeviceStatusParser.kt    // 设备状态解析器
│   │   ├── HistoryDataParser.kt     // 历史数据解析器
│   │   └── MaxMinTempParser.kt      // 最高最低温度解析器
│   │
│   └── model/
│       ├── RealtimeData.kt          // 实时数据模型
│       ├── ParsedDeviceStatus.kt    // 解析后的设备状态
│       └── Feature.kt               // 功能特性枚举
│
└── bluetooth/
    ├── BleManager.kt                // 蓝牙管理（已有，微调）
    └── BleConstants.kt              // 常量定义（已有）
```

### 核心接口

1. **DeviceProfile**：设备配置接口，定义设备支持的特征和解析方式
2. **DataParser<T>**：泛型解析器接口
3. **RealtimeData**：通用实时数据模型

### 固件版本兼容策略

- **新固件**（firmwareVersion > 0）：使用 `REALTIME_DATA_CHAR` 一次性读取温湿度+气压
- **老固件**（firmwareVersion == 0 或无）：使用 `TEMP_CHAR` + `HUMIDITY_CHAR` 分别读取

## 泛型架构升级（2026-01-30 追加）

### 新增内容

1. **SensorData 接口** - 传感器数据基类
2. **HistoryRecord 接口** - 历史记录基类
3. **DeviceTypes 字符串常量** - 替代枚举，便于扩展
4. **ThermometerProfile 接口** - 温度计专用配置接口
5. **泛型化 DeviceProfile<T, H>** - 支持不同设备类型

### 架构示意

```
DeviceProfile<T : SensorData, H : HistoryRecord>
    │
    ├── ThermometerProfile (T=ThermometerData, H=TemperatureRecord)
    │       ├── ThermometerV1Profile (老固件)
    │       └── ThermometerV2Profile (新固件)
    │
    ├── PedometerProfile (T=PedometerData, H=StepRecord) [未来扩展]
    │
    └── HeartRateProfile (T=HeartRateData, H=HeartRateRecord) [未来扩展]
```

### 扩展新设备步骤

1. 在 `DeviceTypes` 添加新设备类型常量
2. 创建新的 `SensorData` 实现类（如 `PedometerData`）
3. 创建新的 `HistoryRecord` 实现类（如 `StepRecord`）
4. 创建新的 `DeviceProfile` 实现（如 `PedometerProfile`）
5. 在 `DeviceProfileFactory` 添加工厂方法

## 注意事项

1. **向后兼容**：确保老固件设备能正常工作
2. **最小改动**：尽量复用现有代码，避免大规模重构
3. **渐进式重构**：先实现新架构，再逐步替换旧代码
4. **类型别名**：`RealtimeData` 是 `ThermometerData` 的别名，保持向后兼容
