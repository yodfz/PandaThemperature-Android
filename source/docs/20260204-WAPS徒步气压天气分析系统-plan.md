# WAPS 徒步环境气压天气分析系统 - 开发计划

## 需求背景

在**没有加速度计**的情况下，通过 **GPS（空间裁判）** 与 **气压计（灵敏观测）** 的数据融合，实现可靠的户外天气预警。

核心思想：

- **运动状态**：用 GPS 修正气压计的“海拔偏移”，避免爬升被误判为天气恶化。
- **静止状态**：锁定海拔，将气压变化全部视为“天气趋势”。

现有基础：

- 气压来自 BLE 温湿度计实时数据（`MainViewModel.pressure`），已每 30 秒写入 `TemperatureRecord`（含 pressure、latitude、longitude）。
- `LocationManager` 支持单次/持续 GPS、`getCachedLocation`。
- `WeatherUtils` 已有 `calculateAltitude(p, T)`、`getWeatherDescription(p)`（仅按绝对值，无趋势）。

## 实现方案概述

### 1. 架构分层（模块化，不集中单文件夹）

| 层次          | 位置                                               | 职责                                                          |
| ------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **数据层**    | `data/weather/`                                    | 气压/GPS 时间序列模型、采样缓存、可选从 DB 读历史用于 3h 倾向 |
| **领域/计算** | `utils/weather/`（与现有 WeatherUtils 同目录扩展） | 中值滤波、MSLP 换算、3h 倾向、状态判定、决策表                |
| **协调/驱动** | `ui/viewmodel/` 或独立 `WeatherAlertViewModel`     | 驱动采样、状态机、决策，更新 UI 与通知                        |

### 2. 数据采集与预处理（MVP）

- **气压**：不强制 1Hz；使用当前已有的实时气压流，在 ViewModel 侧做**滑动缓冲**（例如每 1 秒取一次 `pressure` 入队，保留最近 N 个点），对缓冲做**中值滤波（窗口 5）** 得到 smoothed_p。若 BLE 更新不足 1Hz，则用“有则入队”的策略，窗口仍为 5。
- **GPS**：为支持 5 分钟运动判定，需要**周期性位置**。在 WAPS 开启时每 **10 秒** 取一次位置（复用 `LocationManager.getCachedLocation()` 或短超时 `getCurrentLocation`），保留最近 **5 分钟** 的 (lat, lon, altitude, time) 序列。注意：当前定时写入是 30 秒一次，WAPS 需要独立于写入的 10s 节奏（仅在做天气分析时开启）。
- **温度**：用于海拔/MSLP 换算和“温度剧变暂停”。直接使用当前实时 `temperature`；若变化率 |dT/dt| 过大则暂停天气判定（Pro-Tip 可选）。

### 3. 状态判定引擎（5 分钟窗口）

- 输入：最近 5 分钟 GPS 点（约 30 个点，10s 间隔）。
- 逻辑：若 **位移 < 阈值 且 速度 < 阈值** → **静止 (Stationary)**；否则 **移动 (Active)**。
- 输出：`WapsState.Stationary` / `WapsState.Active`。
- 静止时：锁定海拔 = 最近一次稳定海拔（例如进入静止时的 GPS 海拔或气压反算海拔）；气压变化全部归天气。
- 移动时：当前海拔 = GPS 与气压的融合（例如互补滤波或简单取 GPS 海拔）；再做 MSLP 换算与 3h 倾向。

### 4. 计算内核

1. **海平面气压 (MSLP)**
   - 公式：由观测气压 P 与当前海拔 h、温度 T 换算为海平面气压 P0。
   - 可复用 `WeatherUtils` 中气压 ↔ 海拔关系，反推：已知 h、T，由 P 求 P0（或使用标准大气指数关系）。
2. **气压倾向 (Tendency)**
   - 3 小时内 MSLP（或静止时的 smoothed_p）变化量 ΔP（当前值 − 3h 前值）。
   - 需保留 3 小时的历史序列（按 1 分钟或 30 秒聚合一次均可），MVP 可用 30 秒写入的 DB 记录做 3h 查询，或内存滚动窗口。

### 5. 天气判定逻辑表（决策矩阵）

| 状态 | 气压倾向 ΔP (hPa)   | 判定       | 行为                       |
| ---- | ------------------- | ---------- | -------------------------- |
| 任意 | ΔP < -4             | 暴风雨预警 | 推送紧急通知 (Alarm)       |
| 任意 | -4 ≤ ΔP < -2        | 天气恶化   | 更新界面：阴雨/大风        |
| 任意 | +2 ≤ ΔP ≤ +4        | 天气转晴   | 提示：冷锋过境，注意防风   |
| 移动 | 气压降但 GPS 海拔升 | 正常爬升   | 仅更新海拔，不触发天气预警 |

### 6. 节奏与阈值（与文档一致）

- **每 1 分钟**对原始气压做一次平滑（中值滤波），得到用于趋势的序列。
- **每 30 分钟**计算一次斜率/倾向；若斜率突然变陡 → 触发“注意”。
- **每 3 小时**严格对比 ΔP 阈值；若 ΔP < -4 hPa → 触发“警报”。

### 7. 通知与 UI

- **警报 (ΔP < -4)**：系统 Notification（高优先级），点击可进入 App。
- **注意 / 天气恶化 / 转晴**：更新 UI 图标与文案（如 RealtimeDataCard 或单独天气状态区）。

### 8. 可选（Pro-Tips，MVP 可省略）

- 大气潮汐过滤（日 10:00/22:00 高峰扣除）：后续再做。
- GPS 间歇省电（每 15 分钟开一次）：后续优化。
- 温度剧变暂停：若实现成本低则做（如最近 2 分钟 dT/dt 超阈值则暂停判定）。

## 风险与简化（MVP）

- **3 小时数据**：首次启动无 3h 历史时，不触发“警报”，仅显示“数据收集中”；可用 DB 历史 + 实时缓冲凑满 3h。
- **GPS 海拔**：部分设备在室内无海拔，移动时若 GPS 无海拔可退化为仅用气压反算海拔（即不做融合，仅用气压海拔）。
- **省电**：MVP 不实现“每 15 分钟开一次 GPS”，保持 10s 周期；后续可加开关“省电模式”。
