# 蓝牙连接与自动获取温湿度方案 - 开发计划

## 需求背景

用户需要了解：
1. 蓝牙设备是如何连接的？
2. 配对（Pairing）是如何进行的？
3. 握手协议是否与普通蓝牙不同？
4. 如何自动获取温湿度数据？

## 当前实现分析

### 1. 蓝牙连接流程

#### 1.1 扫描设备
- **位置**：`BleManager.startScan()`
- **实现**：使用 `BluetoothLeScanner` 进行 BLE 扫描
- **过滤条件**：按设备名称过滤（`PandaTemperature` 或 `yodfz-temp`）
- **扫描模式**：`SCAN_MODE_LOW_LATENCY`（低延迟模式）

#### 1.2 连接设备
- **位置**：`BleManager.connect()`
- **实现**：调用 `device.connectGatt()` 建立 GATT 连接
- **参数说明**：
  - `autoConnect = false`：不使用自动连接，需要手动连接
  - `TRANSPORT_LE`：使用低功耗蓝牙传输

#### 1.3 服务发现
- **位置**：`BleManager.gattCallback.onServicesDiscovered()`
- **实现**：连接成功后自动调用 `gatt.discoverServices()`
- **服务类型**：
  - **ESS 服务**（标准服务）：`0000181a-0000-1000-8000-00805f9b34fb`
    - 温度特征：`00002a6e-0000-1000-8000-00805f9b34fb`
    - 湿度特征：`00002a6f-0000-1000-8000-00805f9b34fb`
  - **配置服务**（自定义服务）：`12340020-1234-5678-1234-56789abcdef0`
    - 时间同步特征：`12340011-1234-5678-1234-56789abcdef0`
    - 采集间隔特征：`12340021-1234-5678-1234-56789abcdef0`
    - 设备状态特征：`12340022-1234-5678-1234-56789abcdef0`
    - 历史数据特征：`12340023-1234-5678-1234-56789abcdef0`
    - 最高最低温度特征：`12340024-1234-5678-1234-56789abcdef0`
    - 重置最高最低温度特征：`12340025-1234-5678-1234-56789abcdef0`

### 2. 配对（Pairing）机制

#### 2.1 当前实现
**重要发现**：当前代码中**没有显式的配对逻辑**。

#### 2.2 BLE 配对机制说明

在 Android BLE 中，配对（Pairing）和连接（Connection）是两个不同的概念：

1. **配对（Pairing）**：
   - 建立安全关联的过程
   - 用于交换密钥、建立信任关系
   - 通常在首次连接时进行，之后设备会被"记住"
   - 如果设备需要配对，Android 系统会在 `connectGatt()` 时**自动弹出配对对话框**
   - 这是系统级别的行为，**不需要应用代码处理**

2. **连接（Connection）**：
   - 建立 GATT 连接的过程
   - 用于数据传输
   - 当前实现：直接调用 `connectGatt()` 即可

#### 2.3 配对触发条件

BLE 设备需要配对的情况：
- 设备设置了安全要求（需要加密连接）
- 设备需要绑定（Bonding）
- 设备要求用户确认

**当前设备情况**：
- 从代码来看，设备**不需要配对**（直接连接即可）
- 如果未来设备需要配对，系统会自动处理

#### 2.4 如果需要手动配对

如果未来需要手动触发配对，可以添加以下逻辑：

```kotlin
// 检查设备是否需要配对

    return device.bondState
    // BluetoothDevice.BOND_NONE: 未配对
    // BluetoothDevice.BOND_BONDING: 正在配对
    // BluetoothDevice.BOND_BONDED: 已配对
}

// 创建配对（如果需要）
fun createBond(device: BluetoothDevice): Boolean {
    return device.createBond()
```

### 3. 握手协议

#### 3.1 协议类型
- **标准 BLE GATT 协议**：使用标准的 GATT 服务/特征进行通信
- **无自定义握手包**：不需要额外的握手帧或认证流程

#### 3.2 连接后的初始化流程（类似"握手"）

虽然不需要配对，但连接后有一个**初始化序列**（类似"握手"）：

1. **服务发现**：自动发现 ESS 服务和配置服务
2. **时间同步**：写入当前时间戳到设备（带重试机制，最多3次）
3. **读取配置**：读取采集间隔
4. **读取状态**：读取设备状态（间隔、记录数、连接状态等）
5. **读取温湿度**：读取一次当前温湿度值
6. **读取最高最低温度**：如果设备支持，读取最高最低温度
7. **订阅实时数据**：启用温湿度特征的通知
8. **同步历史数据**：自动获取增量历史数据

#### 3.3 数据格式

- **字节序**：小端序（Little Endian）
- **温度格式**：2字节，单位 0.01°C（例如：2500 = 25.00°C）
- **湿度格式**：2字节，单位 0.01%（例如：6500 = 65.00%）
- **时间戳格式**：4字节，Unix 时间戳（秒）
- **历史数据格式**：每8字节一条记录（4字节时间戳 + 2字节温度 + 2字节湿度）

### 4. 自动获取温湿度机制

#### 4.1 实时数据订阅

**位置**：`MainViewModel.subscribeRealtimeData()`

**实现流程**：
1. **订阅前读取**：如果当前没有数据，先手动读取一次
2. **启用通知**：
   - 温度特征：启用通知，设备会定期推送温度数据
   - 湿度特征：启用通知，设备会定期推送湿度数据
   - 最高最低温度特征：如果支持，也启用通知
3. **数据解析**：在 `onCharacteristicChanged()` 回调中解析数据
4. **状态更新**：更新 `_temperature`、`_humidity` 等状态流

**通知机制**：
- 设备会按照采集间隔自动推送数据
- 无需应用主动轮询
- 数据格式：2字节（温度/湿度）或4字节（最高最低温度）

#### 4.2 历史数据获取

**位置**：`MainViewModel.fetchHistory()`

**实现流程**：
1. **增量获取**：获取本地最后一条数据的时间戳，只获取新数据
2. **写入时间戳**：将起始时间戳写入历史数据特征（4字节，小端序）
3. **订阅通知**：启用历史数据特征的通知
4. **数据接收**：在 `processHistoryData()` 中解析数据包
5. **批量保存**：每20条记录保存一次到数据库
6. **结束标志**：收到 `0xFF` 表示传输完成

**数据包格式**：
- 每条记录：8字节（4字节时间戳 + 2字节温度 + 2字节湿度）
- 结束标志：1字节 `0xFF`
- 超时机制：60秒超时

#### 4.3 自动初始化流程

**位置**：`MainViewModel.initializeDevice()`

**触发时机**：连接成功且服务发现完成后自动执行

**执行步骤**：
1. 同步时间（带重试）
2. 读取采集间隔
3. 读取设备状态
4. 读取一次温湿度
5. 读取最高最低温度（如果支持）
6. 订阅实时数据
7. 自动同步历史数据（增量获取）

**任务进度显示**：使用 `TaskStatus` 显示每个步骤的进度

## 技术架构

### 1. 架构层次

```
MainActivity (UI层)
    ↓
MainViewModel (业务逻辑层)
    ↓
BleManager (蓝牙管理层)
    ↓
Android Bluetooth API (系统层)
```

### 2. 关键组件

- **BleManager**：单例模式，管理蓝牙连接、数据读写
- **MainViewModel**：管理应用状态、业务逻辑、数据同步
- **StateFlow**：响应式状态管理，UI 自动更新
- **Coroutines**：异步操作，避免阻塞主线程

### 3. 状态管理

- **连接状态**：`ConnectionState`（Disconnected / Connecting / Connected / ServicesDiscovered）
- **实时数据**：`StateFlow<Float?>`（温度、湿度、最高最低温度）
- **设备状态**：`StateFlow<DeviceStatus?>`（间隔、记录数、连接状态等）
- **任务状态**：`StateFlow<TaskStatus?>`（显示初始化进度）

## 注意事项

1. **配对机制**：
   - 当前设备不需要配对，直接连接即可
   - 如果未来设备需要配对，系统会自动处理
   - 如果需要手动配对，可以参考文档中的代码示例

2. **握手协议**：
   - 使用标准 BLE GATT 协议
   - 无自定义握手包
   - 连接后的初始化序列类似"握手"流程

3. **自动获取温湿度**：
   - 使用通知机制，无需轮询
   - 设备按采集间隔自动推送数据
   - 历史数据支持增量获取，提高效率

4. **错误处理**：
   - 时间同步有重试机制（最多3次）
   - 历史数据有超时机制（60秒）
   - 所有操作都有异常处理和日志记录

5. **兼容性**：
   - 兼容不同固件版本（例如：最高最低温度特性可能不存在）
   - 使用特性可用性检查，避免崩溃

## 总结

1. **连接方式**：使用标准 BLE GATT 连接，无需配对
2. **握手协议**：标准 GATT 协议，连接后执行初始化序列
3. **自动获取**：使用通知机制，设备自动推送数据
4. **数据同步**：支持实时数据订阅和历史数据增量获取

当前实现已经比较完善，主要需要了解机制和优化细节。
