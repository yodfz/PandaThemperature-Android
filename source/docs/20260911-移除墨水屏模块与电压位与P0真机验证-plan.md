# 20260911 移除墨水屏模块、首页电压预留位与 P0 真机验证

## 需求背景

本轮由三件事触发：

1. **P0 必须真机闭环**。上一轮（20260910）留下了 P0 阻塞：交接文档假设「实时 8 字节含电压 / 历史 14 字节含电压」，但从未在真实设备上验证过。本轮连接真机（小米 22081212C，Android 12）完成了验证。
2. **移除独立的 NFC 墨水屏挂件图传模块**。该模块（`data/nfc` + `EInkPendantScreen`）与温湿度计主业务无耦合，是独立的第二硬件（STM32 + ST25DV16K + 三色墨水屏），不再需要保留在 App 内。
3. **首页设备名称右侧缺少电压预留位**。用户观察到设备名后没有电压位置。

## P0 真机验证结果（关键，与既有假设不符）

验证方式：`adb install` 安装 Debug APK → 启动 → 自动连接已保存设备 → 抓取 `MainViewModel` 标签下的 `BLE诊断` 日志。

实测设备：`PandaTemp_7086`，固件版本 **v2**。

| 项目 | 交接文档原假设 | 真机实测 | 结论 |
|---|---|---|---|
| 实时数据帧长 | 8 字节（6 基础 + 2 电压） | **6 字节** | 不含电压字段 |
| 实时帧样例 | — | `97 09 5F 13 81 27` | 解析为 24.55°C / 49.59% / 1011.3hPa，正确 |
| 历史记录格式 | V3（14 字节，含电压） | **V2（12 字节/条，无电压）** | 与固件 v2 的 Profile 映射一致 |
| 历史帧实际长度 | — | 4B / 12B / 60B（BLE 分包） | 60B = 5 条整，12B = 1 条整 |
| 历史总记录数 | — | 1751 条，接收 1778 条 | 正常 |

原始日志摘录：

**核心结论：这台设备的固件不上报电压。** 实时 6 字节、历史 V2 12 字节，两条路径都没有电压字段。因此首页电压显示为空**不是 App 解析失败**，而是固件确实没有该数据。这直接解释了用户观察到的「没有电压位」现象。

**未覆盖**：本轮只验证了这一台设备（固件 v2）。8 字节实时帧 / 14 字节 V3 历史记录仍属未验证路径，需要固件侧配合。

## 实现方案

### 一、移除 NFC 墨水屏挂件图传模块

删除（共 13 个文件）：

- `data/nfc/` 整目录（11 个文件，约 1497 行）：`Crc16Ccitt`、`EInkEepromImageSender`、`EInkFtmImageSender`、`EInkImageEncoder`、`EInkNfcImageSender`、`EInkNfcProtocol`、`EInkTriColorQuantizer`、`Iso15693`、`NfcPresenceDetector`、`St25dvEInkLayout`、`St25dvFtm`
- `ui/screen/EInkPendantScreen.kt`
- `ui/screen/EInkImageEditor.kt`（已是死代码，删除前全仓库无引用）

清理引用：

- `MainActivity`：移除墨水屏选图 launcher、`selectedEInkBitmap` 状态、`loadBitmapFromUri` 及对应 MainScreen 参数
- `MainScreen`：移除 `homeMode` 状态与 `when(homeMode)` 分支、`nfcTagInRange`/`eInkSendState` 收集、墨水屏发送确认弹窗、「打开墨水屏」调试按钮、`toSimpleEInkPreview` 辅助函数、底部导航栏的墨水屏全屏判断
- `MainViewModel`：移除 `HomeMode` 枚举、`setHomeMode`、NFC 在场检测、`EInkSendState`、`sendEInkPreviewOverNfc`、`cancelEInkSend` 及三处 `setHomeMode(HomeMode.DEFAULT)` 调用
- `DeviceSelectionDialog`：移除 `onSelectEInkPendant` 参数、`SavedDeviceList` 的同名参数与「墨水屏挂件」入口按钮
- `DeviceTypes`：移除 `EINK_PENDANT` 常量
- `AndroidManifest.xml`：移除 `NFC` 权限与 `android.hardware.nfc` 特性声明

**不动**：温湿度计的 BLE 主流程、协议解析、数据库、气压逻辑。

### 二、首页电压预留位

`StatusBar.kt` 的电压原先为「有数据才渲染」（`isConnected && batteryVoltage != null`），无数据时整块消失，视觉上就没有预留位。

改为连接后常驻显示：有电压显示实际值，无电压显示占位符 `-- V`，与 `HistoryCard` 的既有占位约定保持一致。这样布局不会因为数据到达与否而跳动。

### 三、Release 使用调试密钥签名

用户明确表示签名问题先不处理，用 Android 默认调试密钥自动签名即可。

`app/build.gradle.kts` 在原「有 `keystore.properties` 用正式签名」的基础上，增加缺失时的回退：退回 `signingConfigs.getByName("debug")`，使 `assembleRelease` 产出可直接安装的 `app-release.apk`。

> 注意：该回退仅用于本地联调，不可分发。一旦补齐正式 `keystore.properties`，release 产物签名会改变（届时需先卸载旧包）。
